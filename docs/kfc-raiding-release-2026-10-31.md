## Runtime and operations

The existing `kfc-community-calendar` process runs the new schedule extension;
`wow-forever-raids` continues to process native controls and roster updates.
There is no additional bot account or dependency installation.

Private configuration and durable state live under `.data/kfc-raiding/`:
`config.json`, `state.json`, `opening-week.json` and daily operation journals.
Configuration contains exact destination/binding IDs, not credentials. Tokens
stay in the existing `.env.local`. Directories are 0700 and state files 0600.

```sh
# Read-only schedule preview and status, from the Discord website repository.
node_modules/.bin/tsx scripts/kfc-raiding.ts
node_modules/.bin/tsx scripts/kfc-raiding.ts --status

# One applying reconciliation; normally the calendar worker already does this.
node_modules/.bin/tsx scripts/kfc-raiding.ts --apply

# Reviewed campaign source and copy; no writes by default.
node_modules/.bin/tsx scripts/kfc-forever-opening-week.ts
```

`kfc-raiding-setup.ts --apply` provisions the exact KFC layout and retains its
bindings; a completed setup is a no-op. `kfc-forever-opening-week.ts --apply`
publishes the reviewed campaign using deterministic request keys and durable
creation receipts. Do not delete those receipts and rerun to repair a post.
Uncertain creations are held for reconciliation, not blindly retried. Use the
existing event editor for later schedule/rule changes; rewriting the original
campaign source does not silently replace an established agreement.

Native projections synchronize only their owned name/start/finish/cancellation
fields. Manual edits are held, Interested members are retained and deleted
Events are not recreated. The worker reuses its one native Event list per
cycle; eight separate Event reads caused rate limiting during live verification
and were replaced with a tested batch. Future owned forum threads are reopened
after inactivity when appropriate, preserving moderator locks.

Alert subscriptions use the pinned bell reaction. Stable subscriptions do not
require repeated per-member lookups or undo manual role edits. Removing a
reaction revokes only a role assigned by this worker. Digests cover raids in the
next 24 hours, after 18:00 Europe/Berlin, once per edition/day; no eligible raids
or subscribers means no digest. Routine decisions never ping everyone/here.
